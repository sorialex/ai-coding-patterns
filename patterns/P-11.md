# P-11: Desktop-only HTML layout

## Example

```html
<!-- Built for 1440px — fails at 390px -->
<div class="flex items-center justify-between">
    <div>logo</div>
    <div class="flex items-center gap-6">
        <button>Gallery</button><button>Categories</button>
        <!-- ... 6 more labelled buttons ... -->
    </div>
</div>
```

At 390px, 8 labelled buttons exceed nav width. `justify-between` pushes the button
group to the right; the browser wraps the second flex child to a new line. The page
renders a two-row nav on mobile, which the agent considers finished.

## Why it happens

The agent generates layout for the viewport it can reason about implicitly — desktop.
Mobile layout requires conditional reasoning (what changes at what width, what collapses,
what scrolls) that the agent defers unless explicitly instructed. The agent also does not
validate across viewport sizes; once the layout renders at the implied target size, the
task is complete.

## Why it's a problem

Mobile users see a broken layout the agent considers finished. The failures are compounded
by three CSS traps the agent consistently falls into:

1. **`overflow-x: hidden` on `body` is ignored by iOS Safari.** The correct form is
   `html { overflow-x: clip }` — `clip` creates a clipping context without a scroll
   context, so `position: sticky` elements keep working. `hidden` on `body` is
   propagated to the viewport in most browsers, but Safari ignores it entirely.

2. **A flex container cannot reliably serve as both scroll container and flex row.**
   The correct pattern requires a separate scroll wrapper:
   - Scroll wrapper: `overflow-x: auto; flex: 1; min-width: 0` (constrained, scrolls)
   - Inner flex row: `flex-wrap: nowrap; width: max-content` (always full content width)

3. **`overflow-x: auto` on a flex child without `min-width: 0` has no effect.** The
   flex algorithm lets the child expand to its content width instead of constraining it,
   so no overflow is produced and no scrollbar appears.

None of these are caught until the page is opened on a physical device or in
responsive DevTools with a narrow viewport.

## Measure

```
When building or modifying any HTML layout containing navigation, multi-column grids,
or fixed-width components, add at least one mobile breakpoint (≤ 768px). Specifically:

- Nav bars with ≥ 4 items: must scroll horizontally or hide labels on mobile — not
  wrap to a second line. Use a separate scroll wrapper div (overflow-x: auto; flex: 1;
  min-width: 0) containing a flex row (flex-wrap: nowrap; width: max-content).
- Card/candidate grids: collapse to 1 column at ≤ 640px.
- Use `html { overflow-x: clip }` for horizontal overflow containment — not
  `body { overflow-x: hidden }` (ignored by iOS Safari).
```
