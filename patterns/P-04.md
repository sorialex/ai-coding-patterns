# P-04: Re-entry into flow with uninitialized state

## Example

```js
// Another part of the app navigates to the flow
navigateTo('/export')

// The flow mounts but does not reset its state.
// currentStep is still 3 (completed) from the previous session.
// The user lands on the final screen instead of the first step.
```

## Why it happens

The AI implements the flow as an isolated unit. It does not model
that the flow can be reached from external entry points after a
previous completed run. Initialization logic runs once on mount,
not on every activation.

## Why it's a problem

After a successful run, any external navigation back to the flow
lands the user at the last completed state. The entry point and
the flow are each waiting for the other to handle initialization,
so neither does.

## Measure

```
Any flow that can be reached from an external entry point
(navigation, button in another view, external event) must handle
the case where it was previously completed. On external entry,
always verify the flow is in its initial state before activating
it. Do not assume the flow starts cold.
```
