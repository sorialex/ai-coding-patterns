# STATE-01: Flow without reset mechanism

## Example

```js
// States defined: idle → loading → completed
const [status, setStatus] = useState('idle')

// No reset() function exists.
// Once completed, there is no transition back to idle.
```

## Why it happens

The AI implements the forward path of a flow (start → steps → end)
and treats the final state as terminal. It does not model the flow
as something that can be executed multiple times.

## Why it's a problem

The first time a user completes the flow everything works. On any
subsequent attempt — same session or re-entry — the flow is already
in its final state and cannot be restarted without a page reload.

## Measure

```
Any flow with a defined start and end state must include a reset()
function that returns all state to its initial values. This applies
to success, cancellation, and error paths. A "completed" state is
never terminal unless explicitly specified — it is the end of one
iteration, not the end of the flow's lifecycle.
```
