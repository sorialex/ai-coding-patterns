# STATE-03: No state cleanup on flow exit

## Example

```js
// Flow completes successfully and hands control back
setStatus('completed')
navigateTo('/dashboard')

// No reset() called before exit.
// Internal state (currentStep, formData, uploadedFile) persists.
// Next time the flow is activated, it resumes from the last state.
```

## Why it happens

The AI treats the end of the forward path as the end of the flow's
responsibility. It does not consider that the same DOM and state
will be reused in future activations. Hiding a panel or navigating
away feels like a clean exit.

## Why it's a problem

The flow's caller has no reliable way to know what internal state
remains. Any future activation — from any entry point — inherits
leftover state. Fixing it at the entry point is fragile: every
new caller must remember to reset, and one that doesn't creates a bug.

## Measure

```
Any flow with internal state must reset that state before exiting,
on every path: success, cancellation, and error. Do not rely on
the caller to reinitialize the flow. The flow owns its state and
is responsible for leaving it clean before handing control back.
```
